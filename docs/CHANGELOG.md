# 变更记录

## v1.4.0 · 2026-11-10

这一版是把「发白」真正修掉的一次，同时按反馈做了减法。

### 影调引擎重写（`www/js/tone.js`）

上一版用 `brightness(0.8)` 全局压暗来「压高光」，方向就错了：

> 实测那张照片 P99 从 218 掉到 174，动态范围从 203 **缩到 162**。
> 乘法只是等比压扁，永远不会拉开层次 —— 所以用户反馈「完全没有解决」。

现在改成三段式查找表：

1. **黑场归位**：把 P1 拉回接近 0（只回收 60%，留一点脚避免死黑）；
2. **中位锚定**：用伽马把 P50 送到 0.46，整体明暗不偏；
3. **S 曲线 + 高光软膝**：暗部再压、亮部再抬，knee 以上用指数软压缩，不出断层。

白场锚点也修了一个坑：原来用 P99.5，但那张照片 P99.5=248、P98=144，
说明 248 只是零星反光，拿它当白场会把整幅压在下面，高光永远顶不上去。
现在检测到「长尾分布」时改用 P98 加余量。

实测同一张照片：

| 指标 | 原生 | 处理前 | 处理后 |
|---|---|---|---|
| 标准差 | 67.6 | 41.9 | **69.7** |
| 动态范围 | 214 | 219 | **250** |
| P98 | 223 | 144 | **184** |

### 白平衡改白点法

原来用灰世界，结果把青色笔记本机身当成「蓝色偏」强行拉回中性，
通道偏差从 13 降到 4，数字好看但画面更灰 —— 这正是 Buchsbaum 灰世界假设在单色场景失效的经典case。
现在改用 ≥P95 高光区的通道均值估计光源色，限幅 ±10%，3% 内当噪声不动。
同类场景下增益稳定在 1.00/1.00/1.00，机身颜色得以保留。

### 取图路径：不再把好图换掉

`shouldReplacePhoto` 原规则「溢出比例差 > 6% 就换掉原生图」误伤严重：
屏幕、台灯、白墙在 12MP 原生图上本来就是高光，视频流因为动态范围窄把它压平了，
于是每次都判成「原生图偏亮」，把 12MP 换成了 5MP 的视频帧 —— 画质、视野、色彩全崩。
现在只在原生图过半像素死白（>55%）时才弃用。

### 做减法

- **移除定时拍摄**：反馈「没什么用」；
- **移除九宫格**：与取景、画质无关；
- **移除「多摄探测」**：原来会对每个后置摄像头各开一次流再关掉，4 摄机型要开合 4 次，
  每次几百毫秒且画面闪烁 —— 这是卡顿的主因；
- **移除裁切变焦**：裁切冒充变焦只是把中心放大，视频流本来就 4.9MP，再裁更糊。
  现在只用传感器 zoom 能力，设备不支持就不给变焦入口；
- 水印重绘 500ms → 1000ms，影调采样 1800ms → 2400ms 且关掉自动影调时不再采样。

### 水平仪

旧版只读 `gamma`，那只在竖屏成立；横屏时手机的「左右」对应 `beta`，
所以一转屏就彻底失准。现在按 `screen.orientation.angle` 选轴，
并对角度做一阶低通平滑。视觉上也改了：刻度固定、基准线转动，才看得出差多少。

### 横屏布局

原来横屏时取景器只有 309×232（视口 900×420），原因是底部控制条和工具条各占一段文档流高度。
现在两者在横屏下改为浮层，高度全部还给画面 → **500×375**，提升 65%。

### 相机诊断

设置面板底部新增「相机信息」，直接显示本次拍摄的预览流分辨率、
取图路径（`capture` 原生满幅 / `video` 预览流）、成片尺寸、影调参数。
不用连电脑看 console，截图就能定位问题。

### 文献

新增 `docs/ALGORITHM.md`，18 篇文献逐条对应到实现或说明为何不采用。

## v1.3.3 · 2026-11-10

拍摄算法整体过了一遍，四处改动都能用测试量化。

### 对焦评分（`sharpness` → `frameQuality`）
原来把整帧缩到 320px 再算拉普拉斯方差。320px 这一步本身就是低通滤波，高频细节被抹掉，三帧之间的清晰度差异被压平，择优基本等于抽签。
现在改为：取画面中央 62% 区域（主体基本都在这里）、按最高 640px 采样，再算拉普拉斯方差，同时输出「平均梯度强度」用于识别白墙/天空这类本来就没细节的画面。

### 多帧择优
- 三帧之间插入 80ms 间隔。原来仅隔一个 `requestVideoFrameCallback`，两帧内容几乎一样，抓不到手抖和镜头拉风箱造成的差异。
- 选择不再只看清晰度：过曝的帧即使方差更高（高光边缘会拉高方差）也要压分，`score × (1 - min(0.9, 3 × 溢出比例))`。白掉的细节救不回来，清晰没有意义。

### 渐进降采样
单次 `drawImage` 缩放超过 2 倍时，双线性采样会跳过大片像素，出现锯齿和糊边。现在按 `downscalePlan` 逐级减半（4000 → 2000 → 1000），再做最后一次落到目标尺寸。

### 高光保护（百分位）
`tone.js` 的 `analyze` 现在同时算 50 / 98 / 99.5 百分位亮度。在原有档位建议之外加了一层保护：当溢出比例 ≥6% 且 99.5 百分位已经顶到 0.98 以上时，把最亮那撮像素线性压到 0.95。取两者中更保守的一个。晴天天空约占 5% 高光，不会误伤；偏暗场景需要提亮时跳过保护。

### 测试
- 新增 `tests/test-imgproc.js` 15 项：清晰/模糊对比、纯色零分、过曝帧压分、降采样计划
- `tests/test-tone.js` 扩到 26 项：新增百分位、高光保护、提亮不受压三条边界

## v1.3.2 · 2026-11-10

### 修复
- **拍照发白 / 过曝**（用户反馈）。分三层处理，对应三种不同成因：
  1. **快门按得太早**：AE/AWB 没收敛就出片，容易整张惨白。现在按快门前先空跑 3 帧。
  2. **`takePhoto()` 返回偏亮的帧**：部分 Android WebView 上原生满幅拍摄比预览帧明显更白。现在同一时刻再抓一帧，比较高光溢出比例（亮度 ≥250 的像素占比），原生图更糟就换成预览帧，宁可牺牲一点分辨率也不出白片。
  3. **场景本身过曝**：新增 `www/js/tone.js`，按「高光溢出比例 + 平均亮度」给出亮度系数（0.80 / 0.88 / 0.92），用 `ctx.filter = brightness() contrast()` 在 GPU 上压暗并补对比度，作用在水印绘制与签名之前，不影响验真。

### 新增
- 设置面板「亮度」滑块（-30 ~ +30），拍出来发白就直接往左拉，取景器实时生效，成片按同一系数处理。
- 「自动压高光」开关，默认开。阈值偏保守：正常晴天（天空占少量高光）不会被动，只有明显发白才压一档。
- 取景器与成片共用同一套滤镜系数，保证所见即所得（CSS filter 不会渗进 `drawImage`，所以两处都要显式施加）。
- `tests/test-tone.js`：20 项，覆盖溢出比例统计、四档亮度建议、takePhoto 偏亮判定、防抖与 filter 字符串生成。

## v1.3.1 · 2026-11-10

### 修复
- **水印字号没有随画布宽度缩放**（用户反馈「默认字体太大」）。「经典」「卡片」「大字」三种样式的字号只乘了用户设置的 `scale`，漏乘了画布单位 `W / 1080`，因此在任何非 1080 宽的画布上都会按 1080 的绝对像素作画：样式选择面板的缩略图（约 320px）里字大到溢出边界并被截成省略号，取景器实时预览同样偏大。1080p 成片因为 `W / 1080 = 1` 恰好正常，所以这个 bug 只在缩略图和预览层暴露。
- 样式缩略图的底图快照尺寸与画布 backing store 尺寸不一致（CSS px × dpr），底图只铺了左上角一块、文字却按整张画布定位。现统一按 backing store 尺寸取图并绘制。

### 测试
- 排版自检新增「缩放一致性」一组 24 项：同一内容在 2160 / 540 / 420 三种宽度下，首行字号必须与宽度成正比（误差 ≤ 2%）。漏乘 `W / 1080` 会立刻被抓到。总计 240 组。

## v1.3.0 · 2026-11-10

首个开源版本。相对 v1.2.0（源码基线）的主要改动：

### 新增模块
- `www/js/wm-core.js` — 水印渲染引擎。纯函数，不依赖 DOM 之外的任何东西；样式从 6 种扩到 8 种（新增「标签」「印章」），并把尺寸体系改为「以 1080px 宽为基准等比缩放」，1080p / 12MP / 缩略图共用一套代码。
- `www/js/exif-write.js` — 标准 EXIF 写入器。生成 APP1/Exif 段，含 IFD0 / Exif IFD / GPS IFD 三层结构。
- `tests/` — 三套自动化测试（EXIF 往返 11 项、排版自检 216 组、端到端拍摄 14 项）。
- `tools/preview.html` — 水印样式预览台，8 种样式 × 亮/暗底图一次看完。
- `build/build_apk.py` + `build/SignApk.java` — 不依赖 Android SDK 的重打包与签名工具。

### 拍摄算法
- 取图优先 `ImageCapture.takePhoto()` 拿原生满幅照片，失败才退预览帧。
- 预览帧路径改为「连取 3 帧 + 拉普拉斯方差择优」，抵消手抖和虚焦导致的糊片。
- 新增 `composeCanvas()`：把「预览所见」与「成片所得」统一到同一个 source rect 计算，修掉前置镜像、变焦裁切、比例裁切三者叠加时的错位。
- 高画质模式预览请求 2560×1920，成片宽上限 4096px。

### 水印
- 自动取色：采样水印区域亮度，浅色画面用深色墨水、深色画面用白字（原来固定白字，拍雪地/白墙看不见）。
- 位置支持左下 / 右下 / 顶部；字号三档。
- 自定义字段：最多 8 条，`标签：内容` 格式。
- 内容高于画布时自动等比收缩，不再溢出画面。

### 信息与凭证
- 成片写入标准 EXIF：`DateTimeOriginal`、`GPSLatitude/Longitude`（度分秒）、`GPSAltitude`、`GPSTimeStamp`（UTC）、`Make`、`Model`、`Software`、`ImageDescription`。
- 中文走 `UserComment`（UNICODE 前缀 + UTF-16LE）与 `XPTitle`/`XPComment`，系统相册与资源管理器可读。
- 签名段追加 `dev.ver`；验签逻辑不变，向后兼容 v1.2 生成的照片。

### 相机
- 触控对焦（`pointsOfInterest` + `single-shot` 回退）、双指缩放（优先传感器变焦，退裁切）、补光灯、曝光补偿。
- 九宫格、水平仪、定时拍摄（3s / 10s）。

### 交互
- 新增图库面板：本次拍摄历史、批量保存、从相册导入。
- 预览页支持「改水印」：直接用上一张的原图重出水印，不必重拍。
- 设置项分组重排，持久化键升级到 `wmc.settings.v3`（兼容读取 v1/v2）。

### 修复
- **启动图标不再是方图**：原来 `ic_launcher.png` 是 192×192 的不透明方图（无 alpha、四角实色），
  Android 12+ 的系统启动画面把它居中一放，就成了深色屏幕上的一块方块。改为 432×432、
  圆角透明四角，启动画面与桌面图标都干净了。
- `js/exif.js`：`PixelXDimension`/`PixelYDimension` 属 Exif 子 IFD，原实现只在 IFD0 查找，导致读不到图片尺寸。现在两处都看。
- 预览层「重试」按钮被 `.btn-primary{flex:1}` 拉成整列竖条。
- `.tool` 的 `display:inline-flex` 覆盖了 `hidden` 属性，导致不支持的补光灯/曝光控件仍然显示。
- 「改水印」会在已带水印的画布上重复叠加，连点两次就是两层水印。

### 体积
- APK 从基线 337 KB 降到 **108 KB**（图标从 150 KB 优化到 15 KB，其余为前端资源）。
